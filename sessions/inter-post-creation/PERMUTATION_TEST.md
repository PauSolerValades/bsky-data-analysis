# Within-session posting is its own law: a permutation test on post–session alignment

**Status:** definitive result. H0 (session-independent posting) rejected for
100% of testable users at p ≤ 0.001 (resolution limit); the two parametric
shortcuts that would avoid a separate within-session model are both disproved.
This document is the full write-up; `METHODOLOGY.md` carries the summary.

---

## 1. The question

The simulator needs within-session post timings. Two columns were extracted
per user (`dump.py`):

- **interpost_global** — gaps between consecutive posts, session boundaries
  ignored (25.2M gaps). Parametrically fittable: lognorm dominates at 47.2%
  (n ≥ 30 pool), wide support, validated recovery.
- **interpost_within** — gaps between consecutive posts inside the same
  DBSCAN session (11.1M gaps). Parametrically *unidentifiable* in principle
  (session-ceiling truncation; Finding 1 in `METHODOLOGY.md`).

The temptation: the global column is easy to model and the within column is
not — so **derive within from global**. If posts are generated by a single
session-blind process, then within gaps are merely the global gaps that
happen to fall inside session windows, and the simulator needs only the
global model plus the session gate it already has (the staleness rule drops
creates that land past session end). That is one distribution instead of
five, zero new code.

This document shows the derivation fails, proves it with an exact
permutation test, and shows the failure is informative: it rules out not
just the naive gate but also the natural parametric repair
(conditional-truncation sampling), leaving the ECDF as the justified —
rather than merely convenient — choice.

## 2. Hypotheses

Let $\{T_i\}$ be a user's post times and $\{[S_j, E_j]\}$ their session
windows (DBSCAN eps = 300s on all events; production table).

- **H0 (independence):** the post process is independent of the window
  process. Given the gap sequence, the alignment between posts and windows
  is uniform — windows observe the stream, they do not modulate it.
- **H1:** posting is coupled to session state (rate modulation): more posts
  land inside windows than chance alignment allows.

**Test statistic** (per user): the number of *within-session pairs* —
consecutive posts $T_i, T_{i+1}$ falling in the same window:

$$N = \sum_i \mathbf{1}\big[\exists j:\; S_j \le T_i < T_{i+1} \le E_j\big]$$

One-sided: H1 predicts $N_{\text{obs}} > N_{\text{null}}$.

## 3. Why a permutation test, and why circular shifts

**Why not a parametric test.** Any likelihood-based test would need a model
of the post process under H0 — which is heavy-tailed, user-specific, and
serially correlated (burstiness). A wrong null model would confound "the
model is wrong" with "the coupling exists". A permutation test needs no
model of the gaps at all: it conditions on the user's *observed* gap
sequence and randomizes only the quantity H0 says is irrelevant — the
alignment.

**The null ensemble.** Under H0, given (a) the ordered gap sequence and
(b) the window layout, the time origin of the stream relative to the windows
is uniform. The exact randomization is therefore a **circular time-shift**:
wrap the real span $[t_0, t_n]$ into a circle and rotate by
$U \sim \text{Uniform}(0, t_n - t_0)$:

$$T_i^{(r)} = t_0 + \big((T_i - t_0 + U_r) \bmod (t_n - t_0)\big), \qquad r = 1..R$$

This preserves *everything* about the user's behavior — every gap value,
their order, all autocorrelation and burst structure, the window layout —
and destroys *only* the post↔window alignment. It is the maximal
preserving randomization: any residual difference between observed and null
must be attributed to the alignment itself, not to artifacts of the
randomization. (Contrast: an iid bootstrap of the gaps would also destroy
serial structure, leaving the test open to the objection that burstiness,
not alignment, drove the rejection. The shift null forecloses that
objection by construction; the bootstrap is retained below as a *probe*.)

**p-values.** With $R$ null draws $N^{(1)}, \dots, N^{(R)}$:

$$p = \frac{1 + \#\{r : N^{(r)} \ge N_{\text{obs}}\}}{R + 1}$$

(the $+1$ counts the observed arrangement as one of the $R+1$ exchangeable
ones; resolution floor $1/(R+1)$). Users are then combined by **Fisher's
method**: $-2\sum_u \log p_u \sim \chi^2_{2k}$ under H0.

## 4. Result

1,000 users sampled from the ≥30-global-gaps pool (`best_per_user.tsv`);
920 have ≥5 real within pairs and enter the test. $R = 999$ shifts each.

| quantity | value |
|---|---|
| users rejecting H0 at α = 0.05 | **920 / 920 (100%)** |
| median per-user p | **0.001** (the resolution floor) |
| Fisher combined | $\chi^2 = 12{,}679$ on 1,840 df |
| observed / median-null pair count, per user (median) | **21×** |
| null produces < half the observed pairs | 100% of users |

The rejection is not marginal: for essentially every user, *no* random
alignment of their own posting rhythm comes anywhere near the observed
within-session density. Posting is coupled to session state. H0 is dead.

## 5. Decomposition probes (why H0 fails — and why the repair also fails)

The formal test establishes *that* the alignment matters. Three descriptive
replays establish *how*. They are not part of the test and carry no
p-values; they exist to guide the modeling decision.

### Probe 1 — iid replay: rate, not shape

Bootstrap the user's own empirical **global** gaps into a fresh stream
(same span, t0 = first real post), replay against the real windows.

- **Count**: median real/synth ratio 19×; synthetic reaches ≥5 within pairs
  for only 9–11% of users. Confirms the shift-null result is not a
  burstiness artifact (this replay *also* destroys serial structure and
  fails identically).
- **Shape**: among gate-surviving pairs, per-user median(real)/median(synth)
  = **1.02**; p75 identical.

Reading: within gaps are not specially *short* — the same gap lengths occur,
just far more *often* while inside a session. Modulation is in **rate, not
shape**. (Caveat: the shape match is near-tautological. The gate selects the
short component of the global gap mixture, and that component *is* the
within component — see §7. The probe's real content is the count deficit.)

### Probe 2 — conditional-truncation replay: the smart repair, rejected

The natural repair of H0: keep the global model, but inside each session
sample gaps *conditioned on fitting*:

$$x \sim F_{\text{global}}\big(\cdot \;\big|\; x \le \text{remaining session time}\big)$$

walk the session (first post at session start), collect pairs.

- **Count**: median real/cond ratio **0.3×** — the repair *overshoots*,
  producing ~3× too many within pairs (only 0–1% of users underproduced).
- **Shape**: per-user median(real)/median(cond) = **2.03**; cond gaps too
  short across the board (pooled medians 49s vs 95s; p90 205s vs 300s).

Why it fails: conditioning a heavy-tailed law on $x \le$ (small remaining
time) concentrates mass on tiny gaps — shorter than anything real in-session
behavior produces — and re-conditioning on the *shrinking* remaining time
makes successive draws shorter still, a systematic drift the real process
does not have. Note also that the count overshoot is *inconsistent* with
adding a rate multiplier on top (a $\lambda_{\text{session}}$ would push the
surplus higher): the two mechanisms double-count the same boost.

### The verdict the probes deliver

| model for within | count | shape |
|---|---|---|
| global, session-gated (H0) | 19× too few | right |
| global, truncated (repair) | 3× too many | 2× too short |
| **own law (ECDF)** | — | — |

The truth lies strictly *between* the two parametric reductions: within
gaps are shorter than global gaps (something changes when online) but
longer than truncated-global gaps (it is not rejection sampling from the
global law). No deformation of the global distribution reproduces the
within distribution. The within cadence is its own law.

## 6. Consequence for the simulator

All three cheap routes are now closed:

1. **Session-independent posts** (sample global, let the gate produce
   within) — disproved by the permutation test.
2. **Conditional-truncation sampling** from the global fits — disproved by
   Probe 2.
3. **Truncated-likelihood parametric fits** of the within column (e.g.
   fitdistrplus + truncdist) — statistically valid in principle, but the
   truncation point varies per pair (remaining session time, not a fixed
   bound), demanding a custom likelihood, and estimates remain high-variance
   in the Finding-1 regime (ceiling on the bulk; light families only
   separable at T ≥ 900s while within p90 = 281s). Out of scope.

Hence route 4, **ECDF sampling**, chosen by elimination rather than by
convenience: the empirical within distribution (11.1M observations) is
exactly the truncated quantity the simulator must reproduce, at zero
parameters and zero extrapolation risk. Exports: pooled
(`results/within_interpost_ecdf.txt`, 1M lines) and per-global-family
(`results/within_ecdf__<family>.txt`, ≤250k lines each).

## 7. Ontology note — which column is "real"?

Neither test nor probes privilege the global column as the "natural"
process. Users can only post while online, so the generative decomposition
runs the other way: the global column is a **two-component mixture**,

$$g_i = \begin{cases} \text{within gap} & \text{same session} \\ \underbrace{\text{session-}j\text{ remainder}}_{\text{censored}} + \underbrace{\text{offline wait}}_{\text{session arrival}} + \underbrace{\text{session-}(j{+}1)\text{ offset}}_{\text{censored}} & \text{cross-session} \end{cases}$$

and the dominant lognorm global fits are single families stretched over
that mixture — compressions, not behavioral laws. Independence is symmetric:
rejecting $X \perp S$ says the two processes are coupled, not which one
drives. The simulator design reflects the correct direction: sessions and
within cadence are modeled as the two generative components; the global
distribution is never generated — it *emerges* — and survives only as a
user-level heterogeneity **label** selecting which per-family ECDF to load.

The global counterfactual was nevertheless indispensable: only by rejecting
the session-blind model can the two-component design be justified over the
cheaper one-component one. The test licenses the architecture; it does not
describe behavior.

## 8. Threats to validity

1. **Window–post circularity.** Sessions are built from all events
   *including* posts, so windows and post times are coupled by construction.
   Mitigations: likes dominate events ~5:1 over posts, so windows are mostly
   like-defined; and the shift null preserves windows, gaps, and order — the
   rejection isolates the alignment, not window formation. Residual bias,
   if any, inflates the count ratio modestly, not the p ≤ 0.001 floor.
2. **First-post convention in Probe 2** (posting starts at session open).
   Conservative: honoring the real (censored) start offset would only
   increase the synthetic surplus, strengthening the rejection.
3. **Resolution floor.** With R = 999 the smallest reportable p is 0.001;
   the true per-user p-values are likely far smaller (median null count is
   21× below observed). Increasing R is cheap (20s runtime) if the thesis
   needs a tighter bound.
4. **User pool.** The test conditions on ≥30 global gaps / ≥5 within pairs —
   active users. This is the population that matters for the simulator's
   posting dynamics; casual users contribute few posts either way.
5. **Circularity of the span wrap.** Circular shift treats the observed span
   as a torus; for users whose span is dominated by one long gap, a shift
   can concentrate posts artificially. This affects the null, is shared
   across users, and would have to *systematically* deplete within pairs
   21-fold to explain the result — implausible, and the iid probe (no wrap)
   shows the same deficit.

## 9. Reproducibility

```bash
cd sessions
uv run python -u inter-post-creation/independence_test.py --users 1000 --perms 999
```

Runtime ~20s. Output: per-user p-values, Fisher statistic, probe summaries,
pooled quantile table, and `results/independence_ecdf.png` (real vs iid-replay
vs conditional-replay within ECDFs, log-x). Null pair counts are computed by
`within_count` (vectorized), asserted equal to `len(user_gaps(...))` per user.
